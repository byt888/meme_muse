# 策略逻辑说明

> 最后更新: 2026-10-06 (UTC+8)
> 这份文档用白话讲清楚系统"为什么这样设计"。改动历史见 `CHANGELOG.md`，
> 每次改动的决策记录见 `OPTIMIZATION_LOG.md`。

## 1. 目标一句话

在 BSC 上自动发现刚发射、有真实买盘的 meme 币，先用纸面验证稳定盈利，
再经用户授权做小额实盘。**自动交易开关默认关闭，真钱操作必须用户明确授权。**

## 2. 管线总览 (全规则，无 LLM)

```
GMGN trenches (新创建 / 即将打满 / 已开盘)
  → ① 初筛 filters        三阶段阈值，缺字段直接判死 (fail-closed)
  → ② 富化                token info 补"正在浏览人数"，security 复核 honeypot
  → ③ 一票否决 veto        dev 砸盘 / holder 流失 / 回撤 / wash trading 等
  → ④ 生命周期 lifecycle   9 状态机：只有"上涨趋势"才开新仓
  → ⑤ 新闻确认             J7 情报库查催化剂 (路径2: 币→新闻)
  → ⑥ 动量打分 scorer      0-100 分，<60 不开仓
  → ⑦ 风控 limits          仓位映射、并发上限
  → 纸面记录 (自动交易关闭时只记录不下单)
```

## 3. 三阶段初筛阈值 (2026-10-05 用户拍板，坚持不放水)

| 条件 | 新创建 new_creation | 即将打满 near_completion | 已开盘即热 completed_hot |
|---|---|---|---|
| 年龄 | — | < 30 分钟 | < 300 分钟 |
| 市值/池子 | — | 市值 > $5,000 | 池子 > $3,000 |
| 交易数 | > 30 | > 100 | > 800 |
| 总税率 | ≤ 4% | ≤ 4% | ≤ 4% |
| 喊单数 | > 1 | > 1 | > 5 |
| holder 数 | > 10 | > 20 | > 200 |
| 正在浏览 | > 10 | > 50 | > 200 |

原则：缺字段 fail-closed；每个条件独立记录通过/失败，方便统计哪个条件卡最多人。

## 4. 死币定义与活币 M50 (2026-10-06 上线)

**为什么：** 相对估值用"同阶段市值中位数 M50"做锚。实测 55% 的币市值 <$5K
（发射即死），用含死币的中位数当锚，会把真正爆发的币衬托得"太贵"。
死币不配当估值锚。

**死币判定** (`filters.is_dead_for_benchmark`，只用于清洗 M50 分母，不直接筛币)：

- 年龄 ≤ 10 分钟：10 分钟内达不到"交易数 > 10 **且** holder > 5" → 已死
  （发射窗口没起量 = 发射失败，用户原话："毫无价值"）
- 年龄 > 10 分钟：24h 交易数 < 10 **或** holder < 5 → 已死（宽松兜底）
- 关键字段缺失 → 不判死（宁可多算，避免误杀）

**活币 M50** = 剔除死币后，同阶段剩余币的市值中位数。
兜底：活币为空时回退全量中位数，避免打分无锚。

## 5. 一票否决 (veto)

出现以下任何一条，直接淘汰，不看分数：

- dev / 捆绑钱包净卖出（砸盘）
- holder 1 小时流失 > 20%
- 无新催化情况下从高点回撤 > 60%
- wash trading（刷量）
- 经 security 接口复核确认的 honeypot / 开源 / 黑名单问题
  （注意：trenches 的 `is_honeypot` 有误报，必须用 security 接口二次确认）

## 6. 生命周期状态机 (lifecycle)

9 状态（上涨趋势 / 滞涨顶部 / 死亡螺旋 / 超跌企稳 / 二段 …），核心开仓规则：

- 只有 **上涨趋势 (UPTREND)** 才能开新仓
- 满足二段条件的可做 **第二波 (SECOND_WAVE)**
- 滞涨顶部只卖不买；死亡螺旋（回撤>70% + holder 流失>30%）拉黑
- 超跌企稳需要"企稳 + 新催化"双确认，不做纯抄底

## 8. 相对估值 v2：年龄 / 速度双维度 (2026-10-06 上线)

**为什么（用户指出，数据验证）：** 真金狗市值爆发极快（几十 K → 几百 K →
几 M 在数小时内），而扫描是离散的（5 分钟一轮），两次扫描之间有盲区。
一个币可能在盲区里完成第一波暴涨，我们第一次看到它时市值已是中位数的
十几倍。旧逻辑"市值 > 3×M50 直接 0 分"惩罚的恰恰是涨得最快的币 ——
而动量正是金狗的定义特征。拿"平均人"的尺子卡"离群值"，等于系统性错杀赢家。

**v2 规则** (`scorer._valuation_v2`，全确定性）：

- **年轻 + 强动量**（早盘：年龄 ≤ 30 分钟且 5 分钟涨幅 ≥ 30%；
  已开盘：年龄 ≤ 60 分钟且 1 小时涨幅 ≥ 50%）：
  估值用平滑缓衰曲线，不惩罚动量本身 ——
  市值/活币M50 = 1→1.0 分，3→0.83，7→0.5，13→0，之后为 0。曲线连续，无断崖。
- **年老或无动量**：保持旧逻辑 —— 比值越低分越高（1→1.0，2→0.5，3→0），
  > 3 倍判追高，0 分。

**关键澄清：** `valuation=0` 从来不是一票否决，它只是 15% 权重这一项得 0 分。
币是总分 < 60 才被淘汰。一个年轻爆发型金狗即使估值项 0 分，靠动量 25% +
净买入 20% 照样能过 60（合成测试：14 分钟币龄、市值 300K、买盘碾压，
旧打分 58.8 被淘汰 → v2 打分 78.8 通过）。

## 10. 风控与退出规则

详见 `src/risk/limits.py`。核心：

- 分阶段绝对金额上限（百分比风控已废弃，小额账户逐笔亏损）
- 并发数是上限不是目标，绝不为凑数开仓
- **退出规则**（纸面与实盘蓝图一致，`src/risk/exit_sim.py` 确定性模拟）：
  - 硬止损 **-30%**：全平
  - **+100%**：卖 50%（回本金）
  - 剩余仓位：**25%** 峰值回撤移动止盈
  - **+400%**：再卖剩余一半
  - 月球仓：40% 回撤移动止盈
  - 时间止损：**4h** 到期市价全平（胜率按 4h 口径算）
- **费用假设**：GMGN 每笔 1% 手续费 ＋ 2% 滑点假设，即每笔成交按 3% 成本计
  （偏保守，宁可低估收益；待实盘验证）
- 纸面盈亏跟踪：`scripts/paper_pnl_tracker.py` 每 30 分钟用 kline(5m) 回补价格、
  跑退出模拟，`src/risk/pnl_stats.py` 计算"稳定盈利"门禁三标准。

## 12. 数据口径备忘

- trenches API 是**热门列表**，不是全量注册表；不追求与前端名单 1:1 对齐，
  以"API 筛出的币能在前端反向验证"为准。
- `callout_count` = 前端小喇叭喊单数（2026-10-05 与 ZACHXBT 对账一致）。
- `visiting_count`（token info）= 正在浏览人数。
- API 每阶段每轮上限 80 条；主排序 0 通过时按 `swaps_24h` 降序重试一次，
  仍无结果就接受空仓（坚持阈值等行情，不放水）。
